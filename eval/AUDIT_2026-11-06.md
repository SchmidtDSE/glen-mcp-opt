# LLM audit: integer programs

2026-11-06

Three LLMs turned 9 integer word problems into models that HiGHS solved. All 80 completed runs ended with the correct answer. The eval's own pass rate (74/81) understates this because the scorer grades only the last solve. The real gaps are answers given without the solver, spec-format errors that cost retries, and four server reporting gaps.

## Setup

| | |
|---|---|
| Models | `deepseek-v4-flash` (NRP-hosted), `xiaomi/mimo-v2.6-pro`, `anthropic/claude-sonnet-5` — all via open-llm-proxy |
| Problems | 9 ILP/MILP word problems: the 6 integer problems in `problems.json` + 3 new probes (below) |
| Repeats | 3 per model × problem = 81 runs |
| Harness | `eval/run_eval.py`: OpenAI-style tool calling; tools executed in-process against `glen_opt.server`; max 15 turns; default temperature |
| System prompt | "Answer using the available tools. All data is in the question. Finish with the optimal value." |

New probes:

| id | Tests | Expected |
|---|---|---|
| `trays_infeasible` | IP infeasible only because of integrality (4a + 6b = 9) | `infeasible` |
| `crew_schedule` | Cyclic 5-days-on staffing; wrap-around indexing | 23 |
| `facility_location` | 4 × 5 two-index cost table, linking constraints | 230 |

"Final answer correct" was graded from the full last message, not the scorer. "First solve correct" = the first `solve_model` call on the model as stated returned the expected status and objective.

Per problem, every model reached the right answer on every completed run. Scorer PASS counts differ only where noted under Evaluation flaws.

## Text to model

All models chose the right variable types every time: binary for selection and assignment, integer for counts, binary + continuous for fixed charge. None wrote a variable product for `adjacent_parcels`; all linearized it on the first try (binary `z` per pair with `z <= x[i]`, `z <= x[j]`).

Errors came from the spec format, not the modeling. Every run that hit an error recovered and solved.

| Error the LLM made | Model | Count | Server message today | Better |
|---|---|---|---|---|
| Skipped `modeling_guide`, guessed the format | Claude | 9 runs started with a failed call | — | Put the 3 rules below in the `check_model` description; or accept the guessed forms |
| Flat keys `"Ana,S1": 9` for a 2-index param | Claude | 4 | `expected nested object under [Ana,S1]` | Accept `"a,b"` keys, or show the nested form |
| Chained index `cost[r][s]` | Claude | 5 | `only names can be indexed` | Accept it, or say "write `cost[r, s]`" |
| `"forall"` instead of `"for"` on a constraint | Claude | 3 | `unknown name 'r'` (misleading) | `unknown field 'forall'; did you mean 'for'?` |
| Bare labels `x[Mon]` | MiMo | 4 calls (28 messages) | `unknown name 'Mon'` | "`Mon` is an element of set D; quote it: `x[\"Mon\"]`" |
| Spec sent as a malformed JSON string | MiMo | 5, all in one run (4 identical retries) | `invalid JSON … char 1117` | Echo ~40 characters around the error position |
| Param as list of triples `["F1","T1",20]` | MiMo | 1 | `unsupported value` | Accept `[i, j, value]` rows |
| `enumerate`-style loop `d_idx, d in D` | MiMo | 1 | clear | — |

DeepSeek made no format errors. It read the guide on every run, called `check_model` before `solve_model`, and in 7 runs made extra solves to verify the answer (e.g. re-solving with "total <= 22" to prove 23 is optimal) or to offer an alternative (e.g. "at least 9 seedlings" after "exactly 9" was infeasible).

Explanations were in plain terms in all runs. On `trays_infeasible` the server returned `infeasible` with no conflicting constraints; every model worked out the parity argument (4 and 6 are even, 9 is odd) on its own.

## Solver routing

Routing was correct in every run.

| Check | Result |
|---|---|
| Class reported by `check_model` / `solve_model` | ILP for pure-integer, MILP for `fixed_charge`, in all 78 runs that solved |
| Backend | HiGHS in all runs (the only registered backend for LP/ILP/MILP) |
| HiGHS algorithm | MIP branch-and-cut on every integer model (`mip_node_count >= 0`, IPM unused); simplex/IPM/PDLP selection only applies to LPs and HiGHS picks automatically |
| Nonlinear specs (direct test) | `x[i]*x[j]` and `x**2` → class INLP, `status: unsupported`, hint to linearize; no solver call |
| `solver` override (direct test) | `highs` accepted; unknown names rejected |

Direct tests of the server, outside the LLM runs, found four reporting gaps:

| Gap | Observed | Fix |
|---|---|---|
| Unbounded IP | `infeasible_or_unbounded` (HiGHS presolve cannot tell) | On `kUnboundedOrInfeasible`, re-run with `presolve="off"` → `Unbounded` |
| Infeasible IP | No `conflicting_constraints`: HiGHS IIS is LP-only (`getIis` returns invalid) | Run IIS on the LP relaxation; if that is feasible, report "infeasible only because of whole-number requirements" |
| Time limit with no useful bound | `gap: 1.0`, message "within 100.00% of the best possible" | When gap >= 1, say there is no quality guarantee yet |
| Variable bounds that limit the solution | Not in `binding_constraints` (`nest_boxes`: the per-parcel maximums limit the answer, list is empty) | Report variables at a finite bound, e.g. as `binding_bounds` |

## Evaluation flaws

| Flaw | Effect | Fix |
|---|---|---|
| Scorer grades only the last `solve_model` | 4 DeepSeek runs marked FAIL with correct answers (verification or alternative solves came last) | Grade the first solve of the faithful model, or the final message |
| Final answer not graded | A wrong final statement after a correct solve would PASS | Check the final message for the expected value/status (regex is enough for these problems) |
| Answers without tools not flagged | 2 Claude runs answered by hand (correct, unverified); scored FAIL with no reason | Report `no_tool` separately; GLEN's own prompt should require a solve for optimization answers |
| `final` truncated to 300 characters | Answers that state the value later look wrong | Store the full message (done: `messages` now saved per run) |
| API errors not retried | 1 run lost to "Server disconnected" | Retry transient HTTP errors 2–3 times |
| Problems are small | All ≤ 25 variables, solvable by hand; nothing tests scale, SQL sources, time limits, missing data, or nonlinear requests | Add problems with SQL-sourced data, a hard instance with a time limit, a missing-number question, and a nonlinear ask |
| Harness ≠ GLEN | In-process tool calls and a different system prompt than the deployed app | Run a subset through the HTTP MCP endpoint with GLEN's prompt |

## Fixes, prioritized

1. Scorer: grade first faithful solve + final message; flag `no_tool`; retry API errors.
2. Error messages: misleading `unknown name` for unknown fields and bare labels; JSON error context.
3. Accept common guessed forms: `cost[r][s]`, `"a,b"` keys, `[i, j, value]` rows.
4. HiGHS: re-run without presolve on `infeasible_or_unbounded`; IIS via LP relaxation for infeasible IPs.
5. Result: report binding variable bounds; fix the gap >= 100% message.
6. Problem set: add the 3 probes here, plus SQL-data, time-limit, missing-data, and nonlinear problems.

Runs: transcripts per run in the scratchpad `res_*.json` files (spec, tool results, final message).
